### Parse Slack
**ID**: `856221f1-944b-484e-ad42-8429ef857570`  
**Type**: Code Node  
**File**: `nodes/parse-slack.js`

**Purpose**: Cleans Slack formatting and generates correlation_id

**Input**: Raw Slack event from Slack Trigger

**Processing**:
1. Extract text from event
2. Clean Slack formatting:
   - Remove @mentions: `<@U123>`
   - Clean mailto links: `<mailto:test@example.com|test@example.com>`
   - Clean URL links: `<https://example.com|example.com>`
   - Remove remaining angle brackets
3. Generate correlation_id: `corr_TIMESTAMP_USER_RANDOM`

**Output**:
```json
{
  "user_text": "show urgent tickets",
  "user_id": "U09BSMA8U75",
  "channel": "C09BXTD0WR0",
  "thread_ts": "1762451457.804479",
  "correlation_id": "corr_2025-11-06T19-23-45-678Z_U09BSMA8U75_a3f2e1"
}
```

**Critical**: All downstream nodes depend on this output structure

### Handle Plan Response
**ID**: `37fc7cd6-03a7-41a9-9bde-5c4301536520`  
**Type**: Code Node  
**File**: `nodes/handle-plan-response.js`

**Purpose**: Parses OpenAI function call into executable plan

**Input**: OpenAI API response

**Processing**:
1. Extract function name from `tool_calls[0].function.name`
2. Parse arguments from `tool_calls[0].function.arguments`
3. Create plan array with step, action, and parameters
4. Handle clarification questions (no tool_calls but has content)
5. Provide fallback plan if parsing fails

**Output**:
```json
{
  "plan": [
    {
      "step": 1,
      "action": "search_tickets",
      "priority": "urgent"
    }
  ],
  "user_text": "show urgent tickets",
  "channel": "C09BXTD0WR0",
  "thread_ts": "1762451457.804479",
  "correlation_id": "corr_2025-11-06T19-23-45-678Z_U09BSMA8U75_a3f2e1"
}
```

### search_tickets (Build Search Request → Search Text → Filter)
**IDs**: 
- Build Search Request: `7a8c10bf-18ce-47d7-af2f-e9b245dc8991`
- Search Text: `55a1ede6-4217-414b-b94b-0501675c1986`
- Combine Filter Info: `73034a82-b032-4e72-8641-3d7ffc1204d3`
- Client-Side Filter: `27459d00-cc21-4aaa-aa9a-5cb15ca0b6ed`

**Flow**:
1. **Build Search Request**: Creates API request + stores client-side filters
2. **Search Text**: POST to `/api/tickets/search` (text search only)
3. **Combine Filter Info**: Merges request + response
4. **Client-Side Filter**: Applies complex filters

**Why**: Gorgias search API has limited filter support

**Filters Applied**:
- Status (open/closed/pending)
- Priority (low/normal/high/urgent)
- Assignee email (exact or partial)
- Customer email (exact or partial)
- Tags (partial match)
- Date range (from/to)

**ID**: `558e5baa-e157-4638-8a51-c01f957ac6b7`

### Calculate Standard Metrics
**ID**: `3b25ce38-0911-4961-932c-05b605694cd1`  
**Type**: Code Node  
**File**: `nodes/calculate-metrics.js`

**Purpose**: Pre-calculates 100+ metrics in pure JavaScript (0 tokens)

**Processing Time**: ~100-150ms  
**Token Cost**: 0  
**Cost Savings**: ~$0.05-0.10 per query vs. AI calculation

**Metrics Calculated** (5 categories):

1. **Meta**:
   - calculated_at, ticket_count, date_range

2. **Team Performance**:
   - volume (agents, tickets/agent, workload distribution)
   - by_agent (assignments, close rate, resolution time)
   - rankings (by volume, by close rate, by speed)
   - benchmarks (top/bottom performer, averages)

3. **Operational Efficiency**:
   - flow (new today, closed today, velocity, burn rate)
   - backlog (total open, age distribution, oldest age)
   - resolution (avg, P50, P75, P90, P95)
   - priority_distribution, status_distribution

4. **Customer Experience**:
   - customer_metrics (total, active, repeat, high-volume)
   - top_customers (sorted by tickets, with status)

5. **Quality Patterns**:
   - time_patterns (busiest hour/day, distribution)
   - channels (by channel, performance by channel)
   - tags (most common tags with counts)
